# B31 — scoped dashboards and current department snapshots

Issue #39 / TC-02 / TC-14. This is a safe subset, not completed REQ-RPT-01.

## Available interfaces

- GET/HEAD /complaints/dashboard/: current active Complainant's own permitted
  records, or current Head's own department records; Staff/Admin refused.
- GET/HEAD /complaints/departments/<id>/report/: Head of that department only.
  Other-department and Complainant requests return 404; no campus endpoint.
- Department route with format=csv exports exactly the same current-record
  snapshot rows and status/category filters used by its HTML screen.
- Optional exact status/category filters reuse B19's query helper. Unknown keys,
  unsupported status/output and date filters are refused, not silently ignored.

`workflow.dashboards.current_snapshot` reloads the actor and reuses F1's role,
report permission and complaint queryset scoping. One minimal values query
supplies total, exact stored status counts (including zeros), category/location/
department volumes. This is explicitly an all-current-permitted-records view,
not a date-range reporting dataset or an assumed definition of "open". No
complaint body, identity, reference, proof, history reason or source metadata is
selected/rendered/exported. HTML escapes labels; CSV neutralizes formula-like
master-data labels with an apostrophe. Header and links appear on role homes.
Pages/CSV are private/no-store and GET/HEAD cannot mutate complaint records.

`snapshot_csv(snapshot)` formats the same snapshot rows. There is no independent
CSV calculation or broader scope. The exported columns are section,label,count;
formula neutralization changes unsafe label encoding, never numeric figures.
Campus-wide reporting remains owned by F1.

## Outstanding blockers (D03 / B30)

The repository has no F1 B30 shared calculation/export service or approved D03
contract. Issue #8 still requires agreement on date boundaries, dataset inclusion
and mean/median resolution-duration calculations. Therefore B31 does NOT invent:

- A date source, timezone or inclusive/exclusive report range convention.
- Resolution durations across reopen cycles, means or medians.
- Calculated open/overdue/escalated/reopened metrics or policy-dependent reopen
  information. Exact current lifecycle status counts are labelled as such.

Those metrics, date filtering, full department report/CSV acceptance and shared
contract review remain pending. No decision file is changed to imply agreement.
The snapshot service is deliberately isolated for later B30 adapter integration.
This implementation needs no migration and does not change F1/F2/F3 services.
