# B16: Priority and SLA calculation

`effective_priority(indicated, category)` validates the indicated priority and applies the category minimum. The ranking is LOW, MEDIUM, HIGH, CRITICAL; a category may raise the indicated priority, never lower it. With no category, the indicated priority is returned. `Complaint.priority` stores this effective priority; the indicated priority is not persisted separately.

`resolve_sla(category, priority)` returns an `SLAResolution` containing the duration, source (`CATEGORY` or `DEFAULT`), and active configuration. An active category override takes precedence over the active global default. If neither exists, it raises `SLAConfigurationError`.

`compute_due_at(submitted_at, duration_minutes)` requires an aware timestamp and a positive integer duration. It converts the timestamp to UTC before adding elapsed minutes, including across daylight-saving changes, and returns an aware UTC datetime. `derive_priority_and_due(category, indicated_priority, submitted_at)` combines these operations and returns a `PrioritySLA` with the effective priority, due time, duration and source.

SLA and category configuration changes do not rewrite stored complaint priority or due times. The intake adapter will make this call inside the `operation` callback of `execute_intake`, using its trusted server timestamp:

```python
result = derive_priority_and_due(category, indicated_priority, ctx.submitted_at)
Complaint(priority=result.priority, due_at=result.due_at, ...)
```
