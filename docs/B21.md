# B21 complaint history contract

Owner: Tanmay Sridhar (F4). Issue #31; REQ-LIFE-02, NFR-QUAL-03,
BR-03; TC-04, TC-06, TC-07, TC-08.

`record_history(complaint_ref, event_type, actor_kind, previous_state="",
new_state="", remarks="")` retains its existing positional signature.
Use the public Complaint.complaint_id, never an anonymous tracking reference or
its digest. Event and actor values come from ComplaintHistory enums. References
must be nonempty and at most 100 characters; states are at most 50 characters.
State-transition validity and action authorization belong to the calling service.

Call AFTER permission/validation checks and INSIDE the same database transaction
as the operation. History failure must roll back the operation; later operation
failure must roll back history. The writer's atomic savepoint alone cannot make
an earlier, separately committed operation atomic. Do not write success events
from refusal handlers or on_commit callbacks. Retry/idempotency belongs to the
operation (B10 already suppresses replay events); do not deduplicate legitimate
repeated events by timestamp or event kind.

## Event meanings

| Event | Caller/context |
| --- | --- |
| SUBMITTED | F2 accepted intake; empty previous state, SUBMITTED new state |
| ALLOCATED | F2 automatic routing: SYSTEM, SUBMITTED to ASSIGNED; F3 Staff allocation: HEAD, unchanged state |
| REASSIGNED | F3 Head reassignment; unchanged state, required reason |
| ESCALATED | F3 scheduled escalation; SYSTEM, unchanged state, level remarks |
| STATUS_CHANGED | F4 permitted lifecycle transitions, including reopen/close/reject |
| RESOLVED | F4 successful resolution; IN_PROGRESS to RESOLVED |

F4 accepts the existing ALLOCATED routing event: its actor kind and state context
distinguish it from Head allocation. No new enum or historical rewrite is needed.
Every event has a server timestamp; retrieval sorts by timestamp then primary key
to make ties deterministic. Concurrent ordering is recorded timestamp order, not
a promise about distributed or database commit order.

## Reading and privacy

`get_complaint_history` remains a trusted internal lookup, without authorization.
Use `get_authorized_complaint_history(user, complaint_id)` for account-facing
reads. It reloads the current account and applies F1 can_view_complaint rules:
owner and own-department Staff/Head; no Admin content-read privilege is implied.
Missing and unauthorized complaints raise 404. No new public endpoint is added.

ANONYMOUS events discard remarks before persistence. Callers must never place
identity, raw references, reference digests, session data or source metadata in
other fields or in remarks on SYSTEM/STAFF events. The writer cannot identify
arbitrary personal data in free text. F2 reference tracking must use its separate
restricted projection, never this full-history service. #75 owns downstream
anonymous notice/report/CSV integration.

helper are compatible with those additions; the writer docstring edits overlap

Application ORM writes and admin add/change/delete are blocked; privileged SQL
and database maintenance are outside this application-level guarantee. No
database trigger or historical FK backfill is introduced.
