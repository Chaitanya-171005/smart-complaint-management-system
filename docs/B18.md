# B18: Scheduled escalation

`run_escalation(now=None, notify=None)` records a run and processes eligible
past-due complaints in individual transactions. The `run_escalation` management
command runs the scheduled pass. The notification hook defaults to a no-op;
Head notification delivery belongs to F4.

When `run_escalation()` is called inside an outer transaction, notification
callbacks run after the outer commit, after the run has been finalized. A
notification failure then cannot be reflected in the run's error text. The
management command runs without an outer transaction.

A failed complaint transaction is rolled back independently; other eligible
complaints continue and successful transactions remain committed. Any complaint
processing failure marks the run FAILED, with a finished timestamp and counters;
the management command returns a nonzero exit status. Error text is generic so
it does not expose complaint data or exception details. A later run can retry
eligible complaints that failed.

An interruption marks the run FAILED and is re-raised. The interrupted complaint
is counted as failed if its transaction rolled back; an interruption in an
on-commit notification is counted as escalated because its transaction already
committed. Finalization errors do not replace the original interruption. A run
inside an outer transaction is still subject to that transaction's rollback.
The notification hook remains a no-op pending F4/B24; scheduling is outside B18.
