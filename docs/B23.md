# B23 — owner confirmation (issue #33, TC-09)

`workflow.confirmation_service.confirm_resolution(actor=..., complaint_id=...,
expected_revision=..., rating=None)` uses B20's locked account transaction and
writer. Obtain the revision with `get_transition_revision(...,
target_state="CLOSED")`. Only the current active originating Complainant can
confirm RESOLVED work. Rating is absent or a strict integer 1–5 (bools, floats
and strings are refused by the domain service). Closure time/rating, status,
append-only history and B26 CLOSED notices/email jobs commit or roll back
together. Existing B26 recipient rules notify department Head(s), the assigned
Staff and owner when currently eligible; SMTP is not called by confirmation.
Stale or duplicate revisions cannot create a second closure.

The owner detail page links to `/complaints/<id>/confirm/`. GET is read-only;
POST requires login, CSRF and revision, with optional rating. No reference,
state override, file or arbitrary input field is accepted. Successful POST
redirects to the existing owner-only detail. There is no new evidence access.

## Blocker

F2 B13 anonymous-reference authorization is absent at this base. The existing
`complaints.references.hash_reference` is an encoding helper, not an authorized
reference action boundary. No reference lookup or new authorization capability
is invented. Even a valid issued reference cannot confirm here. Anonymous
confirmation and F2 review remain required before issue #33 can be complete.
The F1 owner permission remains unchanged; anonymous users cannot obtain the
full record or proof through these routes. No schema or migration is needed.
