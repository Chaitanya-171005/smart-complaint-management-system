# Q01: cross-module security and privacy validation (REQ-SEC-01/02/03/05/06, BR-03)

Checked on the integrated Main (PR #98), SQLite and PostgreSQL. Two test files, run with the normal suite:
- `test_q01_security_validation.py` walks the real URL configuration, so routes added later are covered.
- `test_q01_access_matrix.py` drives one complaint through every role and department via real URLs.

## Acceptance criteria and where each is checked
| Criterion | Check |
|---|---|
| Authentication and object / department / assignment restrictions | Signed-out GETs only reach reviewed `PUBLIC_ROUTES`. For one complaint, the owner and own-department Staff/Head can read it; another complainant, other-department Staff and Head, and the Administrator get the same answer as for a missing complaint. Progress, resolve, confirm, reject-resolution and assign are refused for every unauthorised role and leave status, department, assignee, rating, reopen count and history unchanged. |
| Evidence downloads enforce parent-object permissions | Download works for the owner and own-department Staff/Head with private, no-store, nosniff headers and no user-chosen file name; everyone else gets the same 404 as a missing file; path and query tricks do not reach the file. |
| CSRF on state-changing actions | No view is `csrf_exempt`; every route refuses a POST without a token, signed out and signed in. |
| Input handling, ORM use, output escaping | Code and templates are scanned for `mark_safe`, `\|safe`, `autoescape off`, raw SQL and `csrf_exempt`. A complaint whose title, description and remarks hold script/HTML payloads is rendered escaped on every page that shows it, as owner, Staff and Head; report, audit and department screens escape names. |
| Anonymous identity linkage and reference disclosure | Staff and Head pages (work page, queue, department report) never show the reference digest or any account email, the queue labels the reporter "Anonymous", other complainants and other departments cannot read the complaint, and a history entry for an anonymous complaint drops any actor, assignee and free text passed to it. The B30 report and CSV count anonymous complaints without attributing them. |
| Lookup / enumeration | Refusals match missing records (above). Reference lookup, malformed/unknown references and rate limiting are covered by F2's `complaints/test_tracking.py` and `test_anonymous.py`, which pass in the same run. |
| Permissions enforced on the server | Every check above posts or fetches directly, with forged fields (`status`, `department`, `submitted_by`, `assignee`, `revision`) ignored; Administrator-only screens refuse every other role; no SCMS role is Django staff. |
| Defects, fixes, retest | Below. |

## Results
- No defect found by these checks on the integrated Main. The tests fail when permissions are weakened (checked by temporarily letting the Administrator read complaints, and letting any department read them).
- Observed, by design, not defects: `/complaints/<id>/` and `/complaints/` are the owner's pages and Staff/Head use `/complaints/<id>/work/` and the queue; the Administrator cannot read complaint content (docs/AUTHORIZATION.md); signed-out evidence requests answer 404, like a missing file; anonymous tracking answers 503 until HTTPS, privacy and Redis settings are configured.

## Not covered here
- Production configuration (HTTPS mode, trusted proxy, Redis, SMTP) is deployment readiness, owned by F3; it needs a check on the real deployment.
- Browser-level XSS and clickjacking checks, and a penetration test, are outside these automated tests.
- B09 upload content rules are tested by F2 (`complaints/test_evidence.py`); the 5 MB definition (D02) is still a team decision.
