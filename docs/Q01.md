# Q01: cross-module security and privacy validation (REQ-SEC-01/02/03/05/06, BR-03)

Status: **in progress.** The checks below run now and cover any route added later. The items marked
"waiting" need B09, B12 and B20 on Main (see Dependencies in issue #10).

## Automated by `test_q01_security_validation.py`
| Requirement | Check |
|---|---|
| REQ-SEC-01/02 authentication | Every route is walked from the real URL configuration. A signed-out GET answers 200 only for the reviewed `PUBLIC_ROUTES`; anything else must refuse or send to sign-in. A new public page fails the test until it is reviewed. |
| REQ-SEC-03 CSRF | No view is `csrf_exempt`; the CSRF middleware is on; every route refuses a POST with no token, signed out and signed in. |
| REQ-SEC-02 / BR-03 server-side permissions | Every Administrator screen (`admin_*` and routing `configuration`) refuses Complainant, Staff and Head on GET and POST; Head-only assignment refuses Complainant, Staff and Admin. No SCMS role is Django staff, so the Django admin site cannot widen access. |
| REQ-SEC-02 object access | A direct evidence URL for someone else's file, or a missing id, answers 404 the same way. |
| REQ-SEC-05/06 input and output | Application code and templates are scanned for `mark_safe`, `|safe`, `autoescape off`, raw SQL (`.raw`, `.extra`, `RawSQL`, cursor) and `csrf_exempt`. Exceptions need a reason in `UNSAFE_ALLOWED`. |
